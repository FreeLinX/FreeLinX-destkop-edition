FreeLinX

An independent Linux distribution with no GNU code in it: the Linux kernel, a NetBSD userland, the musl C library, everything built with LLVM. This page explains what it is, how it works, how to install, use and build it, and what each of its own commands does.

What FreeLinX is

Most Linux systems are built on GNU: glibc, coreutils, bash, GCC. FreeLinX replaces all of it. The C library is musl, the compiler is clang/LLVM, the everyday commands (ls, cp, sh, awk, …) come from NetBSD, init is runit, and the package manager, the installer and the boot code are FreeLinX's own.

The rule is checked, not promised. Before an image is made, check-nognu.sh reads every ELF file in it and refuses the build if it finds a GCC marker, a glibc interpreter or library, or GNU code linked in statically (it recognises ncurses, readline, gettext and others by their strings).

There are two variants:

  • FreeLinX base: a console system, a shell and xpkg for everything else. This page documents base.
  • FreeLinX desktop (FreeLinX-desk): an Openbox desktop with Firefox and graphical applications, built from the same packages.

The base image has no X11, GTK, Mesa or fonts; those are packages (see A desktop).

Trying it

In QEMU

Make a virtual disk once, then boot the ISO from it. KVM makes it fast; without -enable-kvm everything is 10 to 20 times slower.

qemu-img create -f qcow2 flx.qcow2 20G        # once: this empties the disk
qemu-system-x86_64 -enable-kvm -cpu host -m 4096 -smp 2 \
  -drive file=flx.qcow2,if=virtio,format=qcow2 \
  -cdrom freelinx-base-x86_64.iso -boot d \
  -device VGA,xres=1600,yres=900 \
  -nic user,model=virtio-net-pci

After installing, boot the disk with the same command without -cdrom … -boot d.

  • xres and yres set the screen size; the console and X both take it.
  • For UEFI add -machine q35 and the OVMF firmware (-drive if=pflash,…).
  • "No bootable device" means the disk has no system on it yet: install first.

On a real machine

lsblk                                   # find the USB stick, e.g. /dev/sdb
sudo dd if=freelinx-base-x86_64.iso of=/dev/sdX bs=4M conv=fsync status=progress

Boot from the stick. BIOS and UEFI both work. Secure Boot has to be off: FreeLinX is not signed.

dd erases the target. Check with lsblk that it is the stick.

Installing

The live system opens a root shell. Run xsetup. It asks one question at a time across 13 steps, records each finished step, and an interrupted install continues where it stopped.

The disk layout

PartitionSizeContents
ESP (FLX_BOOT, FAT32)1 GiBthe kernel and Limine, for UEFI and BIOS
BIOS boot1 MiBLimine's BIOS stage
FLX_ROOT (ext4)30% of the disk, 6–64 GiB/, the whole system

The disk needs at least 8 GiB. /etc/fstab and /etc/flx-disk name both ext4 filesystems by UUID, so another disk with the same labels is never mounted by mistake.

How it works

The live medium

The live system is not copied into RAM. It is read from the medium, and only what the session changes is kept in RAM. This is how the live media of other distributions work too.

Limineloads the kernel and the 290 KB initramfs
→
flxlivefinds the volume FREELINX_LIVE, attaches boot/root.sfs to a loop device
→
overlaysquashfs read-only below, tmpfs above for changes (75% of RAM at most)
→
/initdevices, network, then runit starts the services

flxlive is a 46 KB static C program. It is C rather than a script because switching the root needs MS_MOVE, chroot and a loop device, and the userland has no switch_root, chroot or losetup. If anything fails it says why and starts a shell. The medium stays readable at /media/flx.

On the ISO: boot/bzImage (the kernel), boot/initramfs.img.gz (flxlive and a static sh), boot/root.sfs (the system, squashfs with zstd), and Limine.

The installed system

An installed FreeLinX boots the way other installed systems do. It has no initramfs at all, because the storage drivers and ext4 are built into the kernel.

Liminepasses root=PARTUUID=… ro init=/init
→
kernelmounts FLX_ROOT read-only and runs /init from it
→
/inite2fsck -p, remount read-write, /home, /tmp in RAM
→
runitservices start; every console asks for a login
  • An installed system uses about 55 MB of RAM after boot.
  • If e2fsck repairs the root filesystem, the machine restarts. If it finds errors it will not fix, you get a shell.
  • The boot menu has a Rescue shell entry: the filesystems and devices come up, no service starts, and the console is a root shell.
  • On shutdown / is remounted read-only, so the disk is clean when the power goes.

Services and consoles

Services are runit directories in /var/service: shell (the consoles), dbus, ntpd, flxwifi, and sshd when it was enabled. Devices are handled by mdevd, started by /init.

/sbin/flxconsole runs on the screen (tty1 to tty3) and on the serial line (ttyS0):

  • on the live medium it opens a root shell on each console;
  • on an installed system (/etc/flx-installed exists) it runs getty and login, and starts them again after you log out. If getty is missing it opens nothing rather than an unauthenticated shell.

Packages: xpkg

xpkg installs software from the FreeLinX repository: 428 packages, from libraries to Xorg, Firefox and mpv.

xpkg update                 # refresh the index
xpkg search editor          # find packages
xpkg install tmux           # install, with everything it needs
xpkg upgrade                # upgrade everything
xpkg remove tmux
xpkg list -e                # what you installed yourself

Why you can trust what it installs

  • The repository index is signed with Ed25519. xpkg checks it against the key in /etc/xpkg/keys and refuses an index that does not verify.
  • Every archive is checked against its sha256 in the signed index before anything is unpacked.
  • Installs are atomic: an install that fails half way (for example, the disk fills up) is rolled back, and nothing broken stays behind.
  • Every package passes the no-GNU check before it is published.

The repository is on Hugging Face (FreeLinX/packages); xpkg repo add <url> adds another.

A desktop

xpkg install xorg xinit openbox      # pulls in fonts, the st terminal and the keymaps
startx
  • Right-click the desktop for the menu: Terminal, Reconfigure, Restart, Exit.
  • Without ~/.xinitrc, startx starts openbox with an st terminal.
  • Your own ~/.xinitrc should end in exec openbox --startup st. A terminal started next to openbox can come up before openbox manages the screen and never show.
  • Screen size: xpkg install xrandr, then xrandr -s 1920x1080.
  • Firefox: xpkg install firefox. It needs about 500 MB, which a live session in a 2 GB machine does not have: install first, or give the machine more RAM.

Upgrading

Boot the new release's ISO on the installed machine and run flxupgrade. It replaces the system files on the root partition (/usr, /bin, /sbin, /lib, /init), adds the files in /etc that the new release has and yours lacks, and puts the new kernel and Limine on the boot partition. Your settings, users, packages and /home stay. Then run doas xpkg upgrade.

Systems installed with 1.0.13 to 1.1.x ran from an image in RAM; flxupgrade converts them to run from their disk.

Packages do not need a new ISO: xpkg upgrade is enough.

Building from source

The build runs on any x86_64 Linux machine, needs no root, and produces the same ISO that is released.

1. Host tools

sudo apt install git curl python3 openssl xorriso squashfs-tools cpio xz-utils binutils
sudo apt install qemu-system-x86 qemu-utils ovmf      # only for the QEMU tests

2. The sources, side by side

mkdir FreeLinX && cd FreeLinX
for r in FreeLinX-base src ports drivers; do
    git clone https://github.com/FreeLinX/$r.git
done

3. The toolchain

curl -LO https://github.com/FreeLinX/toolchain/releases/download/v1.0.0/toolchain.tar.gz
tar -xzf toolchain.tar.gz            # -> FreeLinX/toolchain/ (clang, LLD, the musl sysroot)

4. Build

cd FreeLinX-base
sh build-base.sh                     # -> out/freelinx-base-x86_64.iso (+ .sha256)

It takes a few minutes and downloads about 150 MB. What it does:

  1. scripts/mkrootfs.sh copies src/rootfs and installs the base packages (musl, OpenSSL, dbus, the kernel and firmware, toybox, xpkg, musl-dev, …) by name from the signed repository, so the image has a package database. It adds mandoc, less, iproute2, lsof, mksh, stty and tcc, the repository key, and trims what a console system does not use.
  2. It refuses to continue when the source tree has uncommitted changes, when flxconsole would give an installed system a shell instead of a login, when a program needs a missing library, when a graphical program is left, or when check-nognu.sh finds GNU code.
  3. The system is packed as boot/root.sfs; scripts/flxlive.c is compiled into the initramfs; all of it goes on a Limine ISO for BIOS and UEFI.

Command reference

FreeLinX's own commands. Everything else has a manual page: man <command>.

xsetup

xsetup [--list | --status | --reset STEP | STEP...]

Installs FreeLinX, one step at a time. With no arguments it runs every step not done yet, in order.

--list
the 13 steps
--status
which steps are done
--reset STEP
forget a step so it runs again
STEP
run one step on its own, e.g. xsetup setup-sshd

xpkg

flxupgrade

doas flxupgrade [-y] [disk]

Run from the new release's live ISO. Upgrades the installed FreeLinX it finds (or the one on disk), keeping settings, users, packages and /home; converts a 1.0.13–1.1.x install to run from its disk; rewrites Limine's BIOS stage so it matches the new boot loader. -y skips the question.

passwd

passwd [user]

Sets a password, asked twice with echo off. A user changes their own through doas; root can set anyone's. The hash is made by flxpasswd with the C library's crypt(3).

flxadduser

doas flxadduser NAME [--admin]

Adds a user with a home directory and the groups a console user needs (video, audio, storage, input, users), then asks for a password. --admin also adds the user to wheel, which may run commands as root with doas.

flxwifi

flxwifi scan | list | connect SSID [pass] | disconnect | status | off | auto

Wi-Fi on top of wpa_supplicant and dhcpcd. Give the passphrase as FLXWIFI_PASS=… to keep it off the command line. Saved networks reconnect at boot (the flxwifi service runs auto).

startx

startx [client] [-- server options]

Starts X. With no ~/.xinitrc it runs /etc/X11/xinit/xinitrc: openbox (or dwm, twm) with a terminal (st, urxvt or xterm) started once the window manager is ready.

Status and limits

  • Tested in QEMU/KVM only. Every release passes the install and upgrade suites on BIOS and UEFI, but FreeLinX has not yet been tested on real hardware. Reports are welcome.
  • Secure Boot is not supported: switch it off.
  • eMMC disks (some low-cost laptops) cannot be the install target yet: their driver is a kernel module, and the installed system boots without an initramfs.
  • Wi-Fi firmware for Intel, Atheros, Realtek and MediaTek ships, but Wi-Fi has only been tested against a virtual access point.
  • A few repository programs misbehave when run without what they expect: nvi crashes on start, and lemonbar and the imlib2 demos crash when there is no X display.
